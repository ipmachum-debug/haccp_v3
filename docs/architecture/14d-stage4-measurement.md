# 14d. 4단계 역할별 사용 측정 — 진행 방법 (2026-10-14)

> 근거: 14 문서 §6 "4 역할별 검증" · 13 문서 §5 측정 · 판정 기준(14 §0): **같은 업무를 개편 전·후에 했을 때 클릭·화면 이동은 줄고, 기능과 권한은 그대로.**
> 순서 (Codex 권고, CEO 승인): **작업자 → 품질 → 회계 → 관리자**
> 숫자가 나빠지면 되돌린다. 화면 삭제(폐기) 결정은 측정 뒤 별도.

## 1. 도구 — 측정 패널

서버·DB·API 변경 없음. 화면이 시간·클릭·화면 이동·실패 알림을 대신 센다. 기록은 **측정하는 브라우저에만** 남고 CSV 로 내려받아 모은다.

| 할 일 | 방법 |
|---|---|
| 측정 모드 켜기 | 아무 화면 주소 끝에 `?measure=1` (예: `https://millioai.com/dashboard?measure=1`) → 왼쪽 아래 "사용 측정" 패널 |
| 개편 전 / 후 바꾸기 | 패널의 **사이드바 [개편 전] [개편 후]** → 새로고침. 개편 전 = WORK/회계/HACCP 탭 사이드바, 개편 후 = 허브 사이드바. **측정 모드인 그 브라우저에만** 적용 |
| 측정 시작 | 시나리오 선택 + 측정자 이름 → **시작** (로그인 후 첫 화면에서) |
| 업무 중 | 평소처럼 한다. 막히면 메모를 쓰고 **막힘** (어디서 무엇을 찾다가 막혔는지). 중간 지점은 **단계** |
| 끝 | 업무 완료 기준(§3)에 닿으면 **완료**. 포기·중단은 **중단(미완료)** |
| 결과 | **CSV** 로 내려받기 → 파일 이름 그대로 Codex 에게 전달. **비교** 로 전→후 평균을 바로 볼 수 있음 |
| 끄기 | 패널 아래 **측정 모드 끄기** (또는 `?measure=0`) — 사이드바도 원래 설정으로 |

자동으로 세는 것:
- **시간**: 시작 ~ 완료
- **클릭**: 화면 안 모든 클릭 (패널 클릭 제외). 버튼·링크 이름만 남고 입력값은 남지 않는다
- **화면 이동**: 경로가 바뀐 횟수. 같은 화면에서 탭·필터(쿼리)만 바뀐 것은 세지 않는다
- **오류**: 빨간 실패 알림 횟수와 문구
- **막힘·단계**: 측정자가 누른 것

새로고침·사이드바 전환을 해도 진행 중 측정은 이어서 기록된다.

## 2. 진행 원칙

1. **운영 데이터는 측정을 위해 만들지 않는다.** 발주·입고·출고·승인처럼 데이터를 바꾸는 시나리오는 **그날 실제로 해야 할 업무를 할 때** 녹화한다. 가짜 거래를 넣지 않는다.
2. **같은 사람·같은 종류의 업무**로 개편 전·후를 잰다. 학습 효과를 줄이려고 **순서를 번갈아** 한다 (1회차 전→후, 2회차 후→전).
3. 역할별로 **전·후 각 2회 이상**. 한 번의 숫자로 판정하지 않는다.
4. **오늘의 생산 쓰기(P-2)는 검증 전 꺼져 있다** (`TODAY_PRODUCTION_WRITE`). 그 동안 C 는 오늘의 생산 화면의 "기존 화면에서 시작/완료" 링크를 거쳐 진행한다 — 이 상태를 그대로 측정하고, P-2 를 켠 뒤 한 번 더 잰다.
5. 측정 계정은 실제 그 역할의 계정. 관리자 계정으로 작업자 흉내를 내지 않는다 (메뉴·첫 화면이 다르다).

## 3. 역할별 시나리오와 완료 기준

| 순서 | 역할 | 시나리오 (패널 선택값) | 시작 | **완료**를 누르는 때 |
|---|---|---|---|---|
| 1 | worker 작업자 | **C** 하루 생산 | 로그인 직후 첫 화면 | 오늘 배치를 찾아 재고 확인 → 생산 시작 → 자동출고 결과 확인 → 그 배치의 CCP 기록 1건 저장까지 |
| 2 | inspector / monitor 품질 | **Q** 오늘 쓸 기록지 | 로그인 직후 첫 화면 | 오늘 미작성 CCP 기록지 1건 + 체크리스트 1건 저장 (이탈이 있으면 부적합 등록까지) |
| 3 | accountant 회계 | **B** 발주 → 입고 → LOT | 로그인 직후 첫 화면 | 실제 입고 건: 입고 처리 후 그 원재료 LOT 이 재고에 보이는 것 확인까지 |
| 3 | accountant 회계 | **D** 출고 → 재고 확인 | 〃 | 실제 출고 건: 매출(출고) 등록 후 그 제품 재고가 줄어든 것 확인까지 |
| 3 | accountant 회계 | **E** 승인 → 전표 → 마감 | 〃 | 승인 대기 매입·매출 1건 승인 → 만들어진 전표 확인 (월말이면 마감 상태 확인까지) |
| 4 | admin 관리자 | **C** (완료 부분) | 〃 | 진행 중 배치 실적 입력·완료 → 승인 대기 확인까지 |
| 4 | admin 관리자 | **A** 신규 제품 → 배합 → SKU | 〃 | 실제 신규 제품이 있을 때만: SKU 등록까지 |

## 4. 결과 모으기 · 판정

- 측정자는 CSV 를 내려받아 Codex 에게 전달 (파일 이름 `millio-measure-날짜.csv`). 측정 브라우저의 기록은 판정이 끝날 때까지 지우지 않는다.
- Codex 는 CSV 를 합쳐 아래 표를 채운다 (시나리오·역할별 평균, 완료한 측정만).

|---|---|---|---|---|---|---|---|---|
| C | worker | | | | | | | |
| Q | inspector | | | | | | | |
| B | accountant | | | | | | | |
| D | accountant | | | | | | | |

**판정**: 클릭·화면 이동이 줄고 시간이 늘지 않으며, 오류·막힘이 늘지 않으면 통과. 나빠진 항목은 막힘 메모·경로(CSV 의 `path`)로 원인을 찾아 → 되돌리거나 고친다.
기능·권한 동일은 자동 테스트(라우트 420 접근·역할별 메뉴 스냅샷·API 연결 0 누락)로 이미 확인 중이다.

## 5. 한계 (판정할 때 감안)

- "개편 전" 은 **탭 사이드바로 되돌린 근사치**다. 이미 양쪽 공통으로 들어간 것 — 오늘의 생산·허브 홈 화면, 품질 8종 공통 경로(옛 경로는 리다이렉트), 공통 알림·필터·목록 — 은 차이로 잡히지 않는다. 사이드바에서 빠진 항목은 "Deviation 트렌드" 1개.
- 헤더 메뉴 검색(Ctrl+K)·모바일 하단바는 허브 사이드바에서만 보인다 → 개편 후 쪽에만 있는 기능.
- 클릭 수는 입력칸 클릭도 포함한다 (사람이 세던 방식과 같게). 타이핑 양은 세지 않는다.
