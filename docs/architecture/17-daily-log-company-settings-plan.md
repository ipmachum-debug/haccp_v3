## 1. PR-A — 원본 의미 복원 (Codex 재검토 반영, 구현)

### 1-0. 적용 원칙 (Codex 재검토 P1·P2 반영)
- **회사**: 원본 템플릿은 회사 기능 설정 `DAILY_LOG_TEMPLATE_KHACCP_V1` 을 **켠 회사만** (기본 꺼짐, 회사 번호를 코드에 두지 않음).
- **기록**: 켠 회사의 **새로 만드는 일지**에만. 생성 때 서버가 `form_data.templateCode = "khaccp_daily_v1"` 을 찍는다. 화면이 보낸 값은 버리고, 기존 기록의 표시는 바꾸지 않는다.
- **과거**: `templateCode` 없는 기록(승인·제출·초안 모두)은 질문·머리 문구·인쇄가 **이전 그대로**. 소급 없음.
- **해석 고정**: 자동 초안(객체)·문구 빠진 배열을 읽는 기준은 얼린 `LEGACY_V0_*` (이전 기본 질문). 원본 템플릿을 추가해도 과거 기록 재인쇄 질문이 바뀌지 않는다.

### 5-4. C1 한 날짜 한 건 — 순서 (Codex 재검토 P1)
1. **읽기 조사**: 회사·사업장·날짜 중복, `site_id` 소유(h_sites)·실제 사업장, 키를 채울 수 없는 행. 자동 병합·삭제 없음.
2. **승인·백업** 뒤 이행: `unique_key` 컬럼 추가 → **기존 일지 전부에 서버 규칙으로 키 채움**(`daily_log:{tenant}:{site}:{YYYY-MM-DD}`) → 충돌 행은 채우지 않고 보고 → UNIQUE(tenant_id, unique_key) 인덱스.
3. **부팅 검사**: 인덱스 이름·컬럼 구성이 맞을 때만 `ensureDailyLog` 경로를 켠다. 아니면 기존 경로 유지 + 경고.
4. **생성 경로**: 키는 서버가 회사·사업장·날짜로 만든다(입력으로 받지 않음). INSERT … 키 충돌이면 기존 행 재사용(값 불변). 자동 초안·화면 저장·작성 모달·개별 화면 모두 이 함수만.
5. 제약 전에 먼저 배포해야 하면 같은 DB 트랜잭션의 범위 잠금(예: 설정 행 `SELECT … FOR UPDATE`)을 **모든 쓰기 경로가 함께** 써야 한다 — 프로세스 메모리 잠금으로 대신하지 않는다. 기본안은 위 1~4 순서.
6. 인수: 키가 비어 있던 과거 일지가 있는 날짜에 자동·수동·재전송 3건 동시 요청 → 기존 1건만, 값 불변.

### 5-5. 운영 안전 항목 (UI 설계와 별도 추적)
- 온습도 무작위 표시 29건·자동 생성+전날 값 116건은 **백업 기준 보고값**이며 태그는 조사 근거일 뿐 전체 수정 범위를 확정하지 않는다.
- 별도 읽기 전용 운영 조사(스케줄러·크론·스크립트·로그·배포 범위, 증거 보존) → 승인된 기록을 바꾸는 작업이 남아 있으면 범위·근거 보고 후 승인받아 차단.
- 과거 값 재계산·정정 표시 대량 삽입·서명 재생성은 하지 않는다.

## 6. 결정 (Codex 재검토 권고 반영)

1. **무작위 표시·자동 생성 기록** — 5-5 운영 안전 항목으로 따로 추적. 이 PR 은 손대지 않는다.
2. **과거 승인 인쇄** — 기본은 보존. 새 템플릿을 소급하지 않는다(1-0). 원본 출력물이 없는 경우의 재구성·정정 표시는 C2 에서 별도 절차.
3. **단지 사업장 1·2** — h_sites 소유·실제 사업장·원기록 작성 경로를 읽기 대조한 뒤 결정. 날짜가 겹치지 않는다는 이유로 같다고 보지 않는다. 일괄 변경·tenant_id 대입 없음. C1 키 이행 전에 확정.
4. **새 문구 기준** — 원본 PDF 로 복원(1-2 A1). 저장된 과거 문구 일괄 수정 승인은 아니다. 다른 회사는 템플릿을 켜는 결정이 곧 선택·확인.

| D1 | `client/src/pages/production/DailyLogSettings.tsx` (`ROUTES.DAILY_LOG_SETTINGS`) | 3단계(기록 선택·템플릿 불러오기 → 구역·대상·회차·기준·문구 → 서버 검사·인쇄 미리보기·확인 후 발행). 기능 켠 회사만 목록에 '일지 설정' 버튼 |
| D2 | `DailyLogV2Form.tsx`, `DailyLogV2Renderers.tsx`, `DailyLogForm.tsx` 분기 | 회사 방식(`dailyLog.mode`)으로 화면 선택. 조회만으로 일지를 만들지 않음('작성 시작'). 인쇄는 기록의 정의 스냅샷으로 영역마다 한 쪽, 승인 전 표시 |
| E | `DailyLogV2Notice.tsx` | 개별 온습도·냉동냉장 화면에 v2 회사만 안내(막지 않음, 이전 기록 열람 그대로) |

**운영에서 켜는 순서 (코드 밖, CEO 승인 뒤 Codex 데이터 작업)**
1. `npx tsx scripts/daily-log-unique-key.ts` 조사 결과 보고 → 승인 → 백업 → `--apply --confirm`. 중복이 남으면 그 날짜는 키를 채우지 않고 앱은 이전 경로 유지.
2. 지티(시험 회사)에 `DAILY_LOG_V2` 켬 → 관리자가 설정 화면에서 발행 → 그 뒤 새로 만드는 일지부터 v2. 단지 적용은 읽기 대조·CEO 확인 뒤.
3. 기능을 켜기 전에는 모든 회사가 이전과 같은 화면·인쇄.
