# 18. BOM·설비 재설계 — 초보자 기준 (설계 v2, 2026-10-19 — Codex 검토 반영)

> 기준: **이 프로그램을 쓰는 회사와 직원의 컴퓨터·프로그램 이해도는 0 이다.**
> "사용자가 내부 구조를 몰라도, 실제 작업에 대한 대답만으로 설정과 생산이 이어지는가" 로 판정한다.
> 새 계산 엔진을 만들지 않는다. 기존 계산(하루 계획 planDay, 원물·공정 환산 massBasis, 버전 선택 selectBomVersion)을 한 곳으로 모아 다시 쓴다.
> 근거: Claude 코드 추적 3건(재료 흐름·설비 흐름·설정 화면) + 운영 사본 읽기(단지) + **Codex 기존 코드 분석·제안 검토 (2026-10-19, 기준 2e6836c0)**.
>
> **v2 에서 바뀐 것 (Codex 정정 채택)**
> 1. 불림 배율을 원료 마스터에서 **실시간 상속하지 않는다** — 원료+작업 방법의 '제안값' 을 새 BOM 작성 때 채택하면 **버전 행에 숫자와 출처를 복사·고정**. 제안값을 바꿔도 승인 BOM·과거 배치는 그대로.
> 2. '완제품 몇 kg' + 배율만으로 % 를 원물 kg 로 확정할 수 없다 — **기준 원물 합계 또는 원물 기준으로 알려진 원료 하나의 실제 투입량**(앵커)이 필요. 완제품량은 확인된 수율·표준 실적이 있을 때만. 근거 없으면 '계산 완료' 로 표시하지 않음.
> 3. 설비 최대 kg ≠ 제품 1회 기준량 — 지금 계약(제품 1회 기준량으로 회차)은 그대로, **용량은 초과 검사에만** 먼저 쓴다. 자동 회차 변경은 별도 검증 뒤.
> 4. '3대 묶음' 의 뜻(정확히 3대 / 최대 3대 / 3대 합쳐 한 작업)과 잔량 처리는 **단지 실제 예로 승인받아 정한다**. #598 의 '가용 대수로 줄이기' 는 임시 동작.
> 5. 그림은 2단계 — A. 지금 데이터로 그릴 수 있는 **분류도**(원료 → 전처리 → 지정 공정 → 설비), B. 사용자가 답한 연결만 버전별 **흐름**으로 저장. 미확인 연결은 선을 긋지 않고 '미확인'. MIXED(판매 세트)를 제조 합류로 쓰지 않는다.
> 6. 금속검출 '모든 제품 통과' 는 **회사 규칙**으로 저장 (코드로 모든 회사에 강제하지 않음). 복수 금속검출기는 지원 전까지 설정에서 막는다 (기록지 LIMIT 1).
> 7. 버전 표가 있다고 불변이 아니다 — 승인 버전 편집 차단·새 초안 복제·생산일별 버전 선택·**회사 소유 검증**을 먼저 보완해야 '승인 후 고정' 이라고 말할 수 있다.
> 8. '고급 보기로 숨기기' 는 계산 정리가 아니다 — 어느 값이 계산을 지배하는지 보이고, 기존 값으로 초안 → 전후 차이 → 전환. 두 방식이 동시에 계산되지 않게.
> 9. 직접 투입 ≠ 후첨 — 원료 투입 상태: 지정 공정 / 직접 투입 / 후첨 / 아직 모름. 물은 재고 차감 제외여도 배합·공정 투입에는 남는다.
> 10. 정비 대상 범위: 과거 버전 전체가 아니라 **ACTIVE 보고서의 현재 선택 버전 76개 · 783줄 (공정 미지정 135줄)**. 미지정 ≠ 오류. 일괄 소급·일괄 1.4 금지.

## 1. 분석 요약 — 지금 있는 그대로

### 1-1. 설정 화면 (생산까지 17단계, 마법사 없음)
가입 → 업종 → 회사정보 → 부서·직급·구성원 → 문서결재 → 기능 스위치 → 카테고리 → 거래처 → 품목·SKU → 중간재 → **설비** → **공정 그룹(한계기준·설비 배정·시간)** → **품목제조보고** → 승인 → 공정-제품 수동 연결 → 체크리스트·일지 설정 → 생산.
- 가입 때 업종을 묻지 않는다 (`OnboardingPage.tsx:69`). 업종 플러그인은 메뉴·라벨만 정하고 기본 데이터를 넣지 않는다.
- 같은 것을 설정하는 화면이 여러 곳: 품목 4 · BOM 4 · 한계기준 3 · 거래처 2 테이블 · 회사정보 2 · 체크리스트 템플릿 3.
- 설비 마스터의 실제 화면은 'CCP 모니터링 > 설비기준' 탭. `EquipmentManagement.tsx` 는 경로 없음, 시간 프로필(`ccp_time_profiles`)은 화면 없음.
- 품목제조보고를 **승인하지 않아도 배치가 만들어지고**(최신 초안 사용), 보고서가 없으면 원료 투입 없이 조용히 넘어간다.
- 화면 용어: CCP-1B·CCP-4P, time_min, 묶음 순차, 배치 간격, 원물·공정 기준, 전처리 배율, 환산율(구매→기본), DAILY_LOG_V2 …

### 1-2. 재료 흐름
```
입고(포장 환산 1단계) → LOT → [품목제조보고 → 버전 → 원료 줄]
  → 배치: 투입 계획 (이전: 배합비 % × 완제품 kg / 수율 기준: 원물 스냅샷)
  → 자동 출고 (업무일 기준, 소비기한 빠른 LOT) → 완료 → 완제품 LOT → 출고·매출 → 분개
```
- **원료 필요량 계산식이 5곳** (배치 생성 · 미리보기 · 배치 요구량 · 공정 보정 배합 · BOM 화면). BOM 화면에서 본 값 ≠ 실제 차감 값.
- **kg 단위 원료 줄을 % 로 계산** (`batchCRUD.ts` 이전 방식 `ratio/100 × 생산량`, 단위 무시) — 단지 찹쌀떡(떡마루)·흑임자인절미 승인 버전 17줄. *(운영 영향 Codex 확인 필요)*
- **정제수 = 원료 번호 191 고정** (`mfReportCalculation.ts:444`) — 회사 전용 값. 물 판단이 3가지(차감 여부 칸·재고 제외 표시·이름 '정제수').
- 버전: 승인된 버전을 그 자리에서 고칠 수 있음, 새 버전은 원료 없이 생김, 수정은 최신 버전·생산은 최신 승인 버전.
- BOM 원료 → 재고 원료를 **이름 일치**로 잇는 곳이 남아 있음 (`batchCRUD.ts:208-233` — 정체성 정책 위반).
- 중간재 저장 방식 4가지, 중간재만 있는 줄은 계획·차감에서 빠짐.
- '1회 기준' 비슷한 숫자 3개 (1회 기준량 `batch_target_kg` · 기준 완제품량 · 수율조정 중량 합계), 물 뺀 % 따로 저장, 수율 스위치 2개(회사+버전).
- 단지 실제: 원료 줄 1,183 중 % 1,143 · 전처리 배율 1줄 · 수율 기준 켜진 버전 1개 · **공정 미지정 247줄**.

### 1-3. 설비 흐름
```
설비(평상값) → 공정 그룹(한계기준·운전 방식) + 설비 배정 + 시간 프로필(화면 없음)
  → 제품의 공정 = BOM 원료 공정 지정 + 제품 수동 연결 + 금속검출 항상
  → 하루 계획: 회차 = 총량 ÷ 1회 기준량, 가장 먼저 비는 설비, 시각, 투입량, 평상값
  → CCP 기록지 초안(계획값·평상값·'적합' 미리 채움) → 현장 → 시트 확인 → 승인
```
- **설비 용량 칸 없음** — 큰 설비·작은 설비 같은 kg.
- **공정 순서·합류 데이터 없음** — 공정마다 설비 '아침 시작시각' 에서 따로 출발. 단지는 교반 05:00 · 증숙 08:40 · 오븐 09:00 · 금속검출 08:20 으로 순서를 흉내.
- **미리 채운 값이 실측처럼 통과** — 가열·온도·압력과 **품온(제품 중심온도)까지 설비 값으로 채우고 '적합'**. 값마다 '미리 채움/확인' 구분 없음.
- 시간 설정 5곳(설비 기본 가열 · 1회 사이클 · 시간 프로필 · 한계기준 시간 · 투입 간격), 운전 방식 저장 3곳, 압력 단위 MPa/bar 혼재.
- 현장 기록지에서 운영방식·간격·한계기준을 바꿀 수 있음. 금속검출기는 회사당 1대만.

## 3. 목표 구조 — 3층 + 현장

```
[1층 공장]  공정 · 설비 · 운전 방식 · 평상값 · 용량 · 공정 흐름 틀      ← 고정값, 처음 한 번 (관리자)
     ↑ 참조
[2층 제품]  품목제조보고 → 버전 → 원료 줄 (어느 공정 / 처리 전후 무게)  ← 변동값, 버전 보존
     ↑ 참조
[3층 하루]  날짜 · 제품 · 총량                                         ← 매일 사람이 넣는 건 이것뿐
     ↓ 자동
  생산 배수 → 원료 차감(원물 kg) → 공정 투입(공정 kg) → 회차(1회 기준·설비 용량)
  → 설비 배정·시각(흐름 순서·공유 설비) → 기록 초안(평상값)
     ↓
[현장]  내 공정 오늘 작업 순서 → 정상이면 묶음 확인, 다르면 그 칸만 → 사후 몰아서 확인 가능
```
원칙: 질문에 대답만 · 계산은 시스템 · 평상값 초안 · 예외만 수정 · 같은 걸 두 번 묻지 않음 · 버전 보존 · 실수는 프로그램이 막음.

## 4. 1층 공장 설계 (설비)

### 4-1. 질문 (설정 화면 대신)
| 질문 | 저장 |
|---|---|
| 우리 공장 공정을 고르세요 (업종 틀: 떡류 = 교반·증숙·굽기·금속검출) | 공정 그룹 |
| 이 공정은 가열 공정인가요? 몇 도 이상, 몇 분 이상? | 한계기준 |
| ○○기는 몇 대? 이름은? | 설비 |
| 한 번에 최대 몇 kg 넣어요? | **설비 용량 (신규)** |
| 평소 온도 · 압력 · 가열 몇 분? | 설비 평상값 |
| 한 번 도는 데 (넣고 꺼낼 때까지) 총 몇 분? | 1회 사이클 |
| 여러 대를 동시에 / 한 대씩 차례로 / 몇 대씩 묶어서? | 운전 방식 (한 곳에만) |
| 같은 기계를 다른 공정에도 써요? | 공정-설비 연결 (공유 표시) |
| 공장은 몇 시에 시작해요? | 회사 시작시각 하나 (설비별 시작시각 대체) |
| 모든 제품이 거치는 공정이 있나요? (금속검출 등) | 공통 후속 공정 |
| 이 제품군은 어떤 순서로 만들어요? (그림에서 연결) | **공정 흐름 틀 (신규)** |

### 4-2. 정리
- 시간 설정 5곳 → 사람이 답하는 건 **'평소 가열 몇 분' · '한 번 도는 데 총 몇 분'** 두 개. 나머지(한계기준 시간은 법정 기준, 시간 프로필은 제품별 예외)만 고급 보기.
- 운전 방식은 공정 그룹 한 곳 (기록지 레코드·정책 표는 읽기 전용 복사).
- 압력은 화면·저장 모두 한 단위(bar 또는 MPa, 회사 선택 없이 하나로) — 변환은 한 함수.
- 현장 기록지에서 운영방식·한계기준 편집 제거 (관리자 공장 설정에서만).
- 결과 확인: **공장 지도** (공정 → 설비 → 평상값·용량·운전 방식) 한 장.

### 4-3. 공정 흐름 틀
- 제품군(또는 제품) 단위로 '공정 → 공정' 연결과 합류 지점을 저장. 확인된 것만 쓴다 — BOM 공정 지정으로 순서를 추측하지 않는다.
- 계획 계산: 다음 공정 시작 = 앞 공정(들) 끝 시각 이후 (합류는 모든 앞 공정이 끝난 뒤). 흐름 틀이 없으면 지금처럼 설비 시작시각(안내 문구 표시).
- 금속검출 = 흐름의 마지막 공통 공정 → 굽기·성형이 끝난 뒤 시각.

## 5. 2층 제품 설계 (BOM — 품목제조보고에서 출발)

### 5-1. 질문
1. 품목제조보고 PDF·엑셀 올리기 → 원료·% 자동 읽기 → **확인만**.
2. **'평소 한 번 만들 때'**: 원물 기준으로 아는 원료 하나의 실제 투입량과 상태(생/불린/분쇄 — 앵커), 완제품 기준량(확인된 실적이 있을 때). 앵커가 없으면 % 를 kg 로 확정하지 않는다.
3. 원료마다 두 가지:
   - **어느 작업에 넣어요?** → 버튼: 실제 등록 공정 / **직접 투입** / **나중에 넣음(후첨)** / **아직 모름** → 직접·후첨은 합류 위치도 정함, '아직 모름' 은 준비 점검표에 남음.
   - **넣기 전에 무게가 바뀌나요?** → 아니오 = 1:1 · 예 = "처리 전 40kg 이면 처리 후 몇 kg?" → 배율 자동.
4. 전처리 **제안값**: "생찹쌀 + 불림 → ×1.4" 를 원료+작업 방법 단위로 기억 → 새 BOM 작성 때 제안 → 채택하면 **버전 행에 숫자·출처 복사 (실시간 참조 아님)**. 제품별 예외는 그 버전에. 물·재고 차감 제외는 재고 정책일 뿐, 배합·공정 투입에서 빼지 않는다.
5. **공정 흐름도 + 시험 계산**: "475kg 이면 → 교반 5회, 생찹쌀 ○○kg 차감, 교반기 투입 60kg씩" → 맞으면 승인 → 버전 잠금.

### 5-2. 계산 하나로
- `원료 필요량(버전, 계획 완제품 kg)` 한 함수 → 원물 kg(차감) · 공정 kg(투입) · 공정별 1회 투입량.
- BOM 화면 미리보기 · 배치 투입 계획 · CCP 투입량 · 시험 계산이 모두 이 함수.
- 줄 단위: % = 원물 합계 대비 비율, kg = 1회 기준 무게 × 배수. 한 버전에 섞이면 저장 막고 질문.
- 수율 스위치 하나 (회사 스위치 폐지 → 버전에 '처리 전후 무게' 답이 있으면 그대로 적용).
- 숨길 기존 칸(지우지 않음, 고급 보기): 수율조정 중량 · 보정배합(물 뺀 %) · 기준 원물 합계 · 기준 원물 kg — 답에서 자동 계산.

### 5-3. 버전
- 승인 버전 잠금. 고치려면 '새 버전 만들기' (이전 원료·공정 지정·배율 복사) → 수정 → 시험 계산 → 승인.
- 생산은 승인 버전만. 이미 만든 배치·기록은 그때 버전 그대로 (흐름도도 버전별).
- 생산 중지 제품: 생산 목록 제외, 이력 보존.

## 6. 3층 하루 생산 · 현장

- 입력: 날짜 · 제품 · 총량 (또는 '기준 배합 N번'). 같은 제품 한 줄 (#598).
- 회차 = 제품 1회 기준량 (지금 계약 유지). 설비 용량은 **초과 검사** (넘으면 경고·차단) — 자동 회차 변경은 별도 검증 뒤.
- '기준 배합 몇 번' 은 총량의 대체 입력 — 둘을 같이 받아 곱하지 않는다. 같은 제품 추가 생산(separateRun)은 더블클릭 재시도와 구별해 별도 동작으로.
- 생성 버튼이 실제로 일으키는 효과(자동 시작·원료 출고)를 버튼과 결과에 표시한다 — 이 경계는 UI 정리 명목으로 바꾸지 않는다.
- 화면 역할: **BOM = 생산 구조(흐름도)** · **오늘 생산 = 물량 적용한 배정·회차·시간표** · **태블릿 = 내 공정 오늘 작업 순서**.
- 기록 값마다 **초안 / 확인됨 / 수정됨** (누가·언제, 예정·평상값 출처 보존). 측정해야만 아는 값(품온·금속검출 결과 등)은 초안을 만들지 않음. 미래 행은 확인 제출에 포함하지 않음, 값 수정 시 재확인, 확인 시각을 예정 시각으로 바꿔 쓰지 않음.
- 생산 생성 · 생산 완료 · 품질 승인 · 원료 출고/완제품 입고 · 원가 전기 결과를 따로 보여 준다 — 일부 실패를 초록 '완료' 하나로 덮지 않는다.
- 정상이면 회차 묶음 한 번 확인, 다르면 그 칸만. 작업 끝나고 몰아서 확인 가능 (작업 중 반복 클릭 없음).

## 7. 초기 세팅 마법사 + 준비 점검표

```
① 업종 → ② 공정·한계기준 → ③ 설비(대수·용량·평상값·운전 방식·공유) → ④ 공장 시작시각·공통 공정
→ ⑤ 공정 흐름 틀 → ⑥ 원료 기본값(불림 배율·물) → ⑦ 제품 + 품목제조보고 올리기
→ ⑧ 원료별 질문 2개 → ⑨ 시험 생산 확인 → ⑩ 준비 점검표
```
- 업종 틀로 ②③⑤ 의 초안을 미리 채움 (떡류 틀 = 회사 데이터가 아니라 업종 데이터 — 코드 분기 없음).
- **준비 점검표 (제품마다 신호등)**: 승인 버전 · 1회 완제품 kg · 공정 '모르겠음' 0 · 처리 전후 무게 답 · 흐름 틀 · 공정마다 설비·평상값 → 🟢 생산 가능 / 🟡 빠진 것과 그 결과 한 줄 ("가열시간이 없어 시각 계산 불가").
- 마법사는 기존 설정 화면을 순서대로 묶는다 (새 저장소 없음). 중복 화면은 하나만 남기고 나머지는 그 화면으로 안내.

## 11. 대표 확정 사항 (2026-10-19)

**증숙 묶음·회차 (단지)**
- BOM '배치당 총량' = **증숙기 1대 1회 양** (시루 2개). 설기: 시루 2.5kg × 2 = **5kg** · 약식: 시루 17kg × 2 = **34kg**.
- 묶음 = **기본 3대, 최대 3대** 동시 운전 — CCP 는 **묶음당 1번** (설기류). **약식류는 묶음 없이 증숙기 1대(34kg)씩 독립 운전, CCP 는 1회마다.** 앞에서부터 3대씩, 남으면 2대·1대 묶음 (예: 5대분 → 1-2-3, 4-5).
- 마지막 증숙기는 잔량만 — **시루 단위** (설기 시루 1개 2.5kg, 약식 시루 1개 17kg). 오늘 2대·1대만 쓰면 그 대수가 최대 묶음.
- 지금 계획 계산은 묶음을 항상 3대로 채워(5대분 → 6행) 투입량을 나눈다 → **잔량 묶음·1대 기준 투입으로 수정 (PR-1)**.
- 설정 질문은 '증숙기 1대 = 시루 몇 개 × 시루당 kg' — 작업자 단위(시루)로 묻고 kg 은 계산, 잔량도 시루로 표시.

**제조 흐름**
- 단지: [교반] [증숙] [굽기] + [바로 투입: 앙금·고물 등 가공 납품 재료] → **성형** → 금속검출.
- 회사마다 다르다 (소스 공장: 성형 없음·냉각 있음). 흐름은 **회사 설정** — 업종 틀은 제안, 코드 분기 없음. CCP 아닌 단계(성형·냉각·충전·포장)는 그림에만, CCP 기록지 생성 안 함.
- 공정 미지정 원료 = 대부분 '성형에 바로' (가공 납품 재료). 이름으로 자동 분류하지 않고, 제품마다 "나머지는 성형에 바로 → 확인" 한 번 + 예외만 변경.

## 12. 3자 교차검토 (Claude 코드 추적 · Codex 코드 분석 · 백업 교차검토, 2026-10-19)

### 12-1. 셋이 같은 결론
- 질문 → 설정 초안 → 데이터로 그린 그림 → 시험 계산 → 적용. 기존 계산기 재사용, 엔진 교체 없음.
- 회사 설정 / 제품 BOM 버전 / 오늘 계획 / 현장 실제 기록을 분리.
- 공정 소속(process_group_id) ≠ 공정 순서·합류 — 순서·합류는 확인된 것만 따로 저장.
- 원료 배율은 제안값 → 새 버전에만 복사 (과거 버전·118개 미사용 버전 자동 전환 금지). 백업에 채워진 배율은 **멥쌀 1.25 한 줄**뿐 (1.4 는 예시).
- 설비 용량은 쓰는 설비만, 모르는 용량을 추정해 통과시키지 않음.
- 스위치는 회사 '사용 가능' / 버전 '확인·승인됨' / 배치 '그 버전 사용(스냅샷)' 로 분리.
- 신호등 기준 = '분류 안 된 필수 원료·경로 0' (후첨·CCP 비대상은 정상 분류).

### 12-2. 대표 답으로 확정된 것 (분석에서 '확정 불가' 였던 것)
- `batch_target_kg` = **1배치 총 생산량(완제품 기준)**. 품목제조보고 % × 1배치 총 생산량 → 원료별 kg → 공정 분류 → 공정별 1배치 투입량 (교반기 ○kg, 성형에 바로 ○kg). 1배치 = 각 공정 설비 1회.
  실측: 왕찹쌀떡 96kg = 교반 60.1 + 성형 바로 35.9 · 카스테라쑥앙금인절미 119kg = 교반 63.66 + 약식 증숙 3.93 + 성형 바로 51.41.
  설비 '최대 kg' 이 아니라 '공정 투입량' — 백업 분석 지적과 같은 해석.
- 공정 미지정 = 대부분 가공 납품 재료의 **성형 직접 투입** (앙금·고물). 그래도 줄마다 상태를 확인해 저장 (자동 단정 금지).
- 금속검출 자동 포함은 코드에 있음 (`getProcessGroupsForProduct` 가 활성 CCP-4P 를 모든 제품에 추가) → 회사 규칙으로 옮길 대상.
- 증숙 묶음: 설기 최대 3대·잔량 작은 묶음·CCP 묶음당 1번 / 약식 1대씩·CCP 1회마다 (11절).

### 12-4. 대표 결정이 필요한 것 (X1 관련)
대표 원칙 "평상값을 주고 맞는지만 판단" 과 X1 은 같은 방향이다 — 단, **'맞다' 를 누르는 시점이 그 회차의 실제 확인 시점**이어야 한다.
제안: 태블릿에 회차가 끝날 때 '이 회차 정상' 한 번 (평상값 그대로 기록 + 확인 시각·확인자), 다르면 그 칸만 수정. 종이에 먼저 쓰고 나중에 옮기는 회사는 '전사 입력' 으로 표시.

### 12-5. 대표 결정 — 현장 확인 방식 (2026-10-19)
- **현장(태블릿)**: 회차가 끝날 때 '이 회차 정상' 한 번 → 평상값(계획값)이 그 회차의 기록이 되고 **확인 시각·확인자**가 남는다. 다르면 그 칸만 고친다. 아직 끝나지 않은 회차는 누를 수 없다.
- **PC 입력**: 종이에 먼저 쓴 기록은 PC 에서 평상값이 채워진 기록지를 열고 **필요한 칸만 수정**한다. **'전사' 같은 별도 표시는 하지 않는다** (대표 결정 — 표시가 붙으면 인증·점검 때 따로 검증 대상이 된다). 일반 수정과 같이 처리.
- 원칙: 이 프로그램은 양날의 검 — HACCP 기준에 맞는 편의성을 주되, 너무 엄격하면 회사가 쓰지 않는다. 새 표시·필수 절차를 늘리기 전에 '현장 부담이 늘어나는가' 를 먼저 본다.

## 13. 독립 메뉴 「생산 설계」 (대표 결정 2026-10-19)

**이름의 뜻 — 기존 메뉴와 역할 구분**
- **생산 설계**: 무엇을, 어떤 원료와 설비로, 어떻게 만들 것인가 (기준을 정하고 바꾸는 곳 — 관리자·공장장)
- **생산관리**: 오늘 무엇을 얼마나 만들고, 실제로 어떻게 됐나 (매일 쓰는 곳 — 현장)

**구조 (대표 확정 이름·순서)**
```
생산 설계
 ├ 설계 현황        준비 상태 · 수정사항 · 승인 대기 (첫 화면)
 ├ 우리 공장        설비 · 공정 · 평소 운전법 (공장 지도 · 한계기준 · 흐름)
 ├ 제품 배합        제조보고 · BOM · 흐름도 · 시험 계산 (버전)
 └ 변경·적용 이력   무엇이 바뀌었고 어느 생산부터 적용됐는지 (전후 비교)
```
순서 = 설계 순서: 공장(고정 기반)이 먼저, 제품 배합(변동)은 그 위에.
- 중요하고 복잡하며 주로 '수정사항' 을 보는 곳 → 첫 화면과 변경 이력을 앞에 둔다.
- 기존 메뉴(품질 > CCP 모니터링·한계기준, 생산 > 품목제조보고·레시피)는 당분간 두고 새 화면으로 안내 → 단계적으로 옮긴다 (Strangler Fig). 현장 기록(CCP 기록지·일지)은 생산관리·품질에 그대로.
- 경로는 `ROUTES` 상수, 메뉴는 메뉴 레지스트리 한 곳에서 (CLAUDE.md 라우트 단일 출처 원칙).

**개편 순서**
1. 메뉴 + 설계 현황 + 변경·적용 이력 (읽기 전용 — 지금 데이터 그대로)
2. 제품 배합 (배합표 | 공정 흐름도 | 시험 계산 | 버전 잠금·새 버전 복사) — 단지 송편 등 BOM 정리가 바로 필요해서 먼저
3. 우리 공장 (공장 지도 · 질문형 설비·공정 설정 · 평소 운전법 · 흐름)
4. 준비 상태 점검·초기 세팅 안내

### 13-2. 1단계 구현 (2026-10-19)

  열기·뒤로 가기는 아무것도 바꾸지 않는다. 저장이 성공한 뒤에만 다시 읽고, 화면에서 숫자를 빼지 않는다.
- 버전의 자리 구분 (`versionRole`): production(지금 생산에 쓰는 버전 — 승인 우선·최신) · draft(그보다 새 승인 전 수정안) · old(생산에 안 쓰는 옛 버전).
  신호등은 production 버전 기준. 수정안·옛 버전에서 정한 분류는 그 버전에만 남고 지금 생산 상태를 바꾸지 않는다 (수정안을 열면 노랑 '승인 전 수정안').
- 승인 대기: 승인 버전보다 새 수정안만 '승인 대기'. 더 새 승인 버전이 있는 옛 초안·반려는 따로 보여 주고 자동 처리하지 않는다.
  링크는 그 버전 그대로 연다 (`/design/recipes/{보고서}?version={버전}`) — 다른 버전을 열거나 처리하지 않게.
- 수동 제품-공정 연결 (`ccp_process_group_products`): 실제 계획(getProcessGroupsForProduct)이 원료 지정 공정에 없는 것을 CCP 기록에 더한다.
  원료 없이 연결된 가열 공정은 노랑(투입량 빈칸), 그 공정에 설비가 없으면 빨강. 금속검출은 공통이라 제외. 단지 사본: 71건 모두 원료 공정·금속검출과 겹쳐 현재 영향 0.
- 원료를 바꾸면(같은 줄이라도 원료 품목이 다르면) 들어가는 곳을 이어받지 않는다. 분류 감사 기록에 버전 id·번호를 남긴다.
- '나중에 넣음' 은 공정 없이 따로 넣는 원료 — 넣는 시점(어느 공정 뒤인지)은 아직 저장하지 않는다. 필요하면 업무 확인 후 명시적으로 연결.
- 승인 버전 잠금·새 버전 복사(무엇을 이어받는지)는 2c.

### 13-5. 2b 시험 계산 (2026-10-19)
- 제품 배합 상세에 탭 **시험 계산**: 총 생산량(과 원하면 시작 시각)을 넣으면 회차 · 공정별 설비·시각·공정 투입 · 원료 재고 차감 계획을 보여 준다. **저장 없음.**
- 같은 계산을 다시 쓴다 (새 계산식 없음):
  - 회차·설비·시각·CCP 투입: `planCcpForDay` (오늘 생산 미리보기·실제 생성과 같은 함수). `ignoreBusy` 로 그날 잡힌 다른 생산은 빼고 빈 공장 기준.
    시작 시각을 비우면 오늘 생산처럼 설비 작업 시작, 넣으면 그 시각.
  - 원료 재고 차감 계획: 배치 생성과 같은 식 — `batchInputPlan.legacyInputQty`(보정 배합비 우선 % × 계획량, 배치 생성도 이 함수로 바꿈),
    원물·공정 환산이면 `prepareBatchMassBasis` 스냅샷 원물 kg → 원료 단위, 공정 투입(전처리 후)은 따로 표시.
  - 막히는 이유: 미리보기와 같은 사전 검증(CCP 연결 · 환산 계산 실패) — "실제 생산 건을 만들 때 막힘".
- 정밀도: 원료 차감 계획 소수 3자리(배치 투입 저장과 같음), CCP 공정 투입 소수 2자리(계획 함수 그대로).
- 쓰는 버전 = 생산에 쓰는 버전. 수정안을 보고 있으면 그렇다고 안내.
- 실측(단지 사본): 우유설기 5kg → 증숙기1호 08:40~09:14 · 5.17kg (Codex 운영 오늘 생산 미리보기와 같음), 원료 멥쌀 차감 3.2kg / 공정 4kg.
  시험 전후 생산·투입·CCP·재고 거래·감사 기록 수 같음.
- 함께: 배포 전환 중 화면 조각(동적 import) 불러오기 실패 → 한 번만 새로 불러옴(60초 가드), 반복되면 '새 버전 — 다시 불러오기' 안내.
  저장·승인 요청은 다시 보내지 않는다 (Codex #601 확인 6).
